# How to Plug In a New Scenario

ReCAP's core guardrail logic is scenario-agnostic. A **scenario** provides the
simulated working environment — tools, database, system prompt, evidence
detectors — that the agent operates in. The core graph enforces safety contracts
across scenario boundaries without knowing what the tools do.

## Architecture

```
Main Process (Core ReCAP)              Child Process (Scenario)
┌────────────────────────┐             ┌─────────────────────────┐
│  recap/graph.py        │             │  scenarios/your_scenario│
│    think_node          │             │    tools.py             │
│    act_node ──────────────── Pipe ──>│    Tool functions       │
│    observe_node        │             │    System prompt        │
│    check nodes         │             │    Evidence detectors   │
│    routing             │<── Pipe ────│                         │
│                        │             │  runner.py              │
│  ScenarioConfig ◄───── │             │  (serves tool calls)    │
└────────────────────────┘             └─────────────────────────┘
```

The scenario runs in a child process via `multiprocessing.Pipe`. The core graph
sends `(tool_name, args)` tuples and receives `(status, content)` tuples. This
cleanly isolates the simulated environment — you can replace it without touching
any core code.

## Implementing a Scenario

### 1. Create `scenarios/your_scenario/`

```
scenarios/your_scenario/
├── __init__.py
├── tools.py       # Tool functions + domain state (e.g. database)
├── config.py      # Pluggable pieces: detectors, fields, prompt template
└── runner.py      # Child process entry point (Pipe-based tool server)
```

### 2. `tools.py` — Define your tools

Use LangChain's `@tool` decorator. Tools receive string arguments and return
string results. Raise `DeterministicToolError` (from `recap.tools`) when a
deterministic boundary is violated — the core graph will record it as BLOCKED.

```python
from langchain_core.tools import tool
from recap.tools import DeterministicToolError

@tool
def my_tool(arg: str) -> str:
    """Tool description for the LLM."""
    if some_boundary_violated:
        raise DeterministicToolError("boundary violated: ...")
    return f"result for {arg}"

TOOLS_BY_NAME = {"my_tool": my_tool}
```

You can include a database, state management, or any domain logic alongside the
tools. See `scenarios/ecommerce/tools.py` for a full example with a JSONL-backed
retail database.

### 3. `config.py` — Define pluggable pieces

This module is imported by `live_test.py` and must expose these names:

```python
from scenarios.your_scenario.tools import TOOLS_BY_NAME

# Evidence detectors: evidence_name -> (source_tool, regex_pattern)
# When the named tool runs and the regex matches its output, the evidence is
# considered collected.
EVIDENCE_DETECTORS: dict[str, tuple[str, str]] = {
    "session_token": ("verify_identity", r"session=(\S+)"),
    "order_data":    ("lookup_order",    r"status=(\S+)"),
}

# Valid parameter names for argument_constraints in intent certificates.
CONSTRAINT_FIELDS: list[str] = [
    "order_id", "session_token", "email",
]

# Valid evidence type names (must match keys in EVIDENCE_DETECTORS).
EVIDENCE_TYPES: list[str] = [
    "session_token", "order_data",
]

def system_prompt_template(
    task_desc: str,
    tools_available: list[str],
    evidence_map_hint: str,
    obligation_hint: str,
    purified_hint: str,
    authority_vocab: str,
    constraint_fields_str: str,
) -> str:
    """Build the system prompt for your scenario.

    Must instruct the LLM to output an intent certificate JSON block with fields:
    subgoal, proposed_operation, argument_constraints, authority_basis,
    expected_effect, required_evidence.

    Use the provided hints for obligation tracking, evidence maps, and
    purification context — these are generated by the core graph.
    """
    return (
        f"You are a [your domain] assistant.\n"
        f"Task: {task_desc}\n"
        f"Available tools: {tools_available}\n"
        # ... certificate instructions, constraint guidance, etc.
        f"{obligation_hint}{purified_hint}"
    )
```

### 4. `runner.py` — Child process entry point

This function is called in the child process. It receives one end of a
`multiprocessing.Pipe` and must:

1. Initialize any domain state (database, etc.)
2. Loop reading `(tool_name, args)` tuples from the connection
3. Execute the tool and send back `(status, content)` tuples
4. Exit when it receives `None` (shutdown sentinel)

```python
from multiprocessing.connection import Connection
from scenarios.your_scenario.tools import TOOLS_BY_NAME, DeterministicToolError

def run(conn: Connection) -> None:
    """Serve tool calls from the parent process via Pipe."""
    # Initialize your domain state here
    # e.g. database.seed()

    while True:
        msg = conn.recv()
        if msg is None:  # shutdown sentinel
            break
        tool_name, args = msg
        fn = TOOLS_BY_NAME.get(tool_name)
        if fn is None:
            conn.send(("unknown", f"error: unknown tool '{tool_name}'"))
            continue
        try:
            result = fn.invoke(args)
            conn.send(("ok", str(result)))
        except DeterministicToolError as e:
            conn.send(("blocked", str(e)))
        except Exception as e:
            conn.send(("error", f"error: {e}"))
```

## Running

```bash
# Use the default e-commerce scenario
python scripts/live_test.py

# Use a custom scenario
RECAP_SCENARIO=scenarios.your_scenario.config python scripts/live_test.py

# Override task and user request
RECAP_TASK_DESC="Your task description" \
RECAP_USER_REQUEST="Your user request" \
python scripts/live_test.py
```

## Programmatic Usage

```python
from multiprocessing import Pipe, Process
from recap.graph import ScenarioConfig, build_recap_graph, set_llm
from recap.ledger import EvidenceDetector
from recap.tools import MultiprocessingToolExecutor
import your_scenario.config as cfg
import your_scenario.runner as runner

# Start child process
parent_conn, child_conn = Pipe()
child = Process(target=runner.run, args=(child_conn,))
child.start()
child_conn.close()

# Build config
detectors = {
    name: EvidenceDetector(src, pat)
    for name, (src, pat) in cfg.EVIDENCE_DETECTORS.items()
}
scenario = ScenarioConfig(
    tools_by_name=cfg.TOOLS_BY_NAME,
    system_prompt_template=cfg.system_prompt_template,
    evidence_detectors=detectors,
    constraint_fields=cfg.CONSTRAINT_FIELDS,
    evidence_types=cfg.EVIDENCE_TYPES,
    tool_executor=MultiprocessingToolExecutor(parent_conn, child),
)

# Build and run graph
graph = build_recap_graph(scenario).compile()
result = graph.invoke({"messages": [...], "task_entry": task})
scenario.tool_executor.shutdown()
```
